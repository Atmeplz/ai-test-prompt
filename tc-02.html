009【任务】
010
011请阅读随附的科学论文（PDF 文件），并解答以下 3 个问题。每个问题的解答字数限制在 1000 字以内，3 个问题一次性输出。
012
013【问题】
014
0151. 在处理大规模语料（如 500 万文档的 HotPotQA）时，为什么论文更推荐使用稀疏编码器索引而非稠密向量索引？
0162. 为什么混合查询（如 Best Fields）在 CoQA 数据集上相比基础查询（Match Query）没有取得准确率提升？
0173. 论文中提出的多字段混合查询（Multi-match Queries）包含哪四种分类？各自的检索侧重点是什么？

028## 设计说明（对应考察点，不计入提示词）
029
030### 出题意图
031
0321. **PDF 解析能力**：论文以 PDF 附件形式给出，模型须自行解析（图文/表格/公式）——能否读 PDF 是能力决定因素之一
0332. **文本理解与信息提取**：3 个问题均为"论文内可定位的事实题"，考察从给定文本中提取准确信息
0343. **幻觉检测**：小众论文训练语料覆盖少，模型无法凭记忆作答，编造细节（数字/方法/结论）即被抓
035
036### 论文信息
037
038- 标题：Blended RAG: Improving RAG Accuracy with Semantic Search and Hybrid Query-Based Retrievers
039- 作者：Kunal Sawarkar / Abhilasha Mangal / Shivam Raj Solanki（IBM）
040- arXiv：2404.07220v2（2024-08-04），7 页
041- 摘要：提出 Blended RAG——BM25 + 稠密向量（KNN）+ 稀疏编码器（ELSER）三种索引混合查询策略，在 NQ/TREC-COVID/HotpotQA/SQUAD 上刷新检索基准，生成式 QA 上超越微调方法
042
043### 标准答案要点（评分核对用）
044
045**Q1 稀疏编码器 vs 稠密向量（大规模语料）**
046- HotPotQA 5M 文档：稠密索引 ≈50GB，稀疏索引 ≈10.5GB
047- 稠密：索引快/查询慢；稀疏：索引慢/查询快
048- 明确推荐 sparse encoder；企业级建议 multi-tenancy + federated search
049
050**Q2 CoQA 混合查询无提升**
051- CoQA 无元数据（devoid of metadata）
052- Table VI：BM25+MQ/BF=45.3、KNN+MQ/BF=47.56、SE+MQ/BF=49.94——BF 与 MQ 完全一致
053- 元数据是多字段查询有效的前提；SE 语义搜索仍最优
054
055**Q3 四种 Multi-match 查询**
056- Cross Fields：跨字段同时出现
057- Most Fields：多字段多视角文本表示
058- Best Fields：单一字段内词聚合
059- Phrase Prefix：类似 Best Fields，优先短语
